# لوحة مركز إحسان

تطبيق عربي للمشرفين، يعمل على Google Apps Script ويخزن البيانات في ملف Google Sheets خاص بمالك المشروع. لا يحتاج استضافة أخرى أو تثبيت مكتبات.

## الإعداد لأول مرة

1. أنشئ مشروعًا في Apps Script باسم **لوحة مركز إحسان** واضبط توقيته على الكويت.
2. استبدل محتوى `Code.gs` بالكامل بمحتوى الملف المرفق بالاسم نفسه.
3. بجانب **الملفات** اضغط **+ ← HTML**، وسمّ الملف **Index**، ثم استبدل محتواه بالكامل بمحتوى `Index.html`. الاسم حساس لحالة الأحرف.
4. احفظ المشروع. من قائمة الدوال أعلى المحرر اختر `setup` ثم اضغط **تشغيل**.
5. وافق على إذن Google لإنشاء وقراءة جداول البيانات. إذا عرضت Google تنبيه تطبيق غير متحقق، تحقق أنك تشغل مشروعك الذي أنشأته، ثم أكمل مسار التفويض الذي توفره Google لحسابك. إذا منع مشرف المؤسسة التفويض، يلزم الرجوع إليه.
6. افتح **سجل التنفيذ**. ستجد رابط ملف البيانات، واسم المستخدم `admin`، وكلمة مرور مؤقتة. احتفظ بها محليًا؛ لا ترسل كلمة المرور في المحادثة.
7. لا يعيد تشغيل `setup` تعيين الحساب أو مسح البيانات؛ يعرض رابط الملف فقط عند وجود إعداد سابق.

`appsscript.json` مرفق لمن يستخدم أداة رفع الملفات؛ لا يلزم نسخه عند الإعداد اليدوي. يحتوي توقيت الكويت ونطاق الوصول لجداول البيانات فقط.

## الاختبار والنشر

1. اختر **نشر ← اختبار عمليات النشر**، واختر نوع **تطبيق ويب** إذا طُلب ذلك، ثم افتح رابط الاختبار. هذا الرابط للمحررين ويشغل النسخة المحفوظة الحالية.
2. سجّل الدخول ببيانات سجل التنفيذ، وغيّر كلمة مرور حسابك من **الإعدادات ← المشرفون ← تعديل**. بعد تغييرها، سجّل الدخول مجددًا.
3. جرّب الدورة الموضحة أدناه قبل إضافة بيانات حقيقية.
4. للمشرفين، اختر **نشر ← عملية نشر جديدة ← تطبيق ويب**. حدّد التنفيذ بصفتك **أنا**، والوصول **أي شخص** إذا كان حساب Google يسمح بذلك؛ سيظل الدخول داخل التطبيق باسم المستخدم وكلمة المرور. لا تشارك ملف البيانات نفسه مع الجميع.
5. افتح رابط التطبيق الذي ينتهي بـ `/exec` واختبر الدخول، ثم شارك الرابط مع المشرفين.
6. بعد أي تحديث للكود، استخدم **نشر ← إدارة عمليات النشر ← تعديل ← إصدار جديد ← نشر** لتحديث الرابط نفسه.

قد تختلف خيارات الوصول المتاحة حسب حساب Google وسياسة المؤسسة. لا يلزم نشر التطبيق للعامة لاختبار نسخة المحرر.

## أول استخدام

1. راجع الفئات الافتراضية: اليافعين، الشباب، الرجال. يمكن تعديلها أو إضافة فئات.
2. أنشئ موسمًا وحدد بدايته ونهايته وأنواع الأنشطة وأوزانها. يمكن نسخ أوزان موسم سابق.
3. احفظ الموسم كمسودة، ثم فعّله عندما يصبح مجموع الأوزان ١٠٠.
4. أضف الطلاب مع الفئة وتاريخ الانتساب. الهاتف والملاحظات اختياريان.
5. أنشئ لقاءً، وحدد التاريخ ونوع النشاط والفئة. سجّل الحالات واحفظ مسودة أو اعتمد الحضور.
6. راجع ملف الطالب والتقارير. التصدير جدول قابل للفتح في برامج الجداول؛ الطباعة تتيح الحفظ بصيغة PDF من المتصفح.

## الحساب والسلوك

- النقاط لكل نوع = عدد مرات الحضور ÷ عدد اللقاءات المعتمدة المؤهلة × وزن النوع.
- الغياب بعذر يدخل عدد اللقاءات ولا يمنح نقاطًا، مع ظهوره منفصلًا في التقارير.
- تستبعد المسودات واللقاءات الملغاة والمستقبلية. عند عدم وجود لقاءات مؤهلة لنوع، يُستبعد وزنه وتُعاد موازنة النتيجة إلى ١٠٠ من الأوزان المتاحة. لا تظهر نتيجة إذا لم يوجد أي لقاء مؤهل.
- تُحفظ قائمة الطلاب داخل اللقاء المعتمد. إيقاف الطالب أو نقله لاحقًا لا يغير حضوره القديم أو نقاطه السابقة.
- نقل الفئة وإيقاف الطالب يسريان من يوم التعديل بتوقيت الكويت. يحتفظ التطبيق بفترات الانتساب داخليًا لتسجيل لقاءات سابقة بشكل صحيح.
- لا يتغير تاريخ الانتساب بعد وجود سجلات للطالب. لتصحيح حالة حضور، افتح اللقاء المعتمد وعدّلها؛ يعاد الحساب ويُسجّل التعديل.
- تاريخ ونوع وفئة اللقاء المعتمد ثابتة. عند الخطأ فيها ألغِ اللقاء وأنشئ بديلًا؛ يبقى السجل الملغى محفوظًا.
- الأوزان والتواريخ قابلة للتعديل في وضع الإعداد فقط. المدير يعيد فتح الموسم عند الحاجة، ويحفظ التعديلات، ثم يفعله مجددًا.
- إغلاق الموسم يمنع تعديل لقاءاته. يجب اعتماد مسوداته أو إلغاؤها قبل الإغلاق.
- المدير يدير المواسم والفئات وحسابات المشرفين. المشرف يدير الطلاب والحضور ويعرض التقارير.
- نتيجة التقرير تخص الفترة والأنواع المحددة فيه. ملف الطالب يعرض نتيجة الموسم كاملًا.

## البيانات والحسابات

ملف Sheets ينشأ تلقائيًا بست صفحات. الأعمدة الثالثة تحتوي سجلات JSON يقرأها التطبيق؛ تعامل معها كبيانات داخلية ولا تعدّلها أو تفرز جزءًا منها يدويًا. استخدم واجهة التطبيق والتصدير. يمكن نسخ ملف البيانات احتياطيًا من Google Drive.

تخزن كلمات المرور كبصمات HMAC مملحة، مع مفتاح خاص محفوظ في خصائص المشروع. لا تظهر كلمات المرور في الواجهة أو قاعدة البيانات. جلسة الدخول حتى ٦ ساعات وقد تنتهي مبكرًا عند إخلاء Google ذاكرة التخزين المؤقت. تغيير كلمة المرور أو الصلاحية أو إيقاف الحساب يبطل جلساته السابقة. أسماء المستخدمين دون مسافات وكلمات المرور ٨ أحرف على الأقل.

النسخة مخصصة لمركز صغير؛ تقرأ البيانات دفعة واحدة، وبحد أقصى ٣٠٠ طالب في اللقاء. لا توجد رسائل أو إشعارات خارجية أو بوابة طلاب.

## التحقق المحلي

يتطلب التحقق المحلي Node.js 22 أو أحدث، دون تثبيت مكتبات. تعمل الاختبارات تلقائيًا على GitHub عند الدفع إلى `main` أو فتح طلب سحب.

```sh
node --test tests/*.test.cjs
cmp Code.gs install/Code.txt
cmp Index.html install/Index.txt
```

مجلد `install` يحتوي نسخًا نصية لتسهيل النسخ إلى محرر Apps Script. بعد تعديل المصدر، حدّث النسخ قبل الدفع:

```sh
cp Code.gs install/Code.txt
cp Index.html install/Index.txt
```

تختبر الاختبارات منطق الخادم باستخدام بدائل لخدمات Google: الدخول والصلاحيات، إنشاء البيانات، التحقق، احتساب النقاط، قوائم الطلاب، التعارض بين تعديلات الحضور، وإغلاق المواسم. لا تغني عن الاختبار الفعلي داخل حساب Google. تختبر اختبارات الواجهة أيضًا منع تكرار الدخول، تعذّر تخزين الجلسة، فشل الحفظ وإعادة المحاولة، تنقل لوحة المفاتيح داخل النوافذ، والبحث بحروف عربية وفارسية. تستخدم بديلًا مبسطًا للمتصفح؛ لا تتحقق من التخطيط أو قارئ الشاشة.

مراجع Google: [الاتصال بين الواجهة والخادم](https://developers.google.com/apps-script/guides/html/communication)، [اختبار تطبيقات الويب ونشرها](https://developers.google.com/apps-script/guides/web).
